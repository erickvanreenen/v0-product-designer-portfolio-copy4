Why this screen looks the way it does

Numbered points map to the blue chips on the screen above.

1

Guided is the default, Expression is opt-in

The audience is ops, not engineers. Form-based input is the path. Expression mode stays available because some users will want to copy or share rules as text. Switching is non-destructive.

2

The THEN clause is locked to the section

You came here from the Risk warning section, so the rule applies to that section. The system locks the action to prevent whole categories of error. You only define the IF.

3

Each condition is field, operator, value

Familiar pattern from Airtable, Notion, every modern filter UI. The operator changes options based on field type — numeric gives you >, <, between; categorical gives you in / not in; dates give you before / after.

4

AND/OR connector is a visible toggle

Defaults to AND because that's the more common case. Tap to flip to OR. Visible only when two or more conditions exist, so the affordance appears when needed and nowhere else.

5

Plain-English echo closes the loop

The system reads back what the rule will actually do. Confirms the user expressed what they meant. Reused in the stress test (screen 04) to prove the pattern scales to five conditions and nested groups.

6

"Save to library" is opt-in, not the default

Most rules are one-off for one template. The minority that should be reused get promoted to the library explicitly. Avoids the library filling up with throwaway rules from every template.
